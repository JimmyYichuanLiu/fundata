# 数据与指标口径

## 可追溯数据

`fund_store.py` 是基金库共用迁移入口。现有数据先备份，在副本完成迁移和完整性验证，再迁移原库。`schema_migrations` 保存版本；重复执行不会再次改写已迁移数据。

- 净值日期规范为 `YYYY-MM-DD`，兼容八位旧日期。无效日历日期和未来日期不进入有效序列。
- 原始记录保留在 `fund_nav_data`；异常/重复/冲突的证据保留在 `nav_quality_audit`。公开读取使用 `valid_fund_nav`，不是删除异常记录后的新库。
- 同基金同日期相同数值为重复；不同数值保留证据并报失败，不能静默覆盖。邮件重试发现冲突仍为未恢复。
- 来源使用 `data_source`（`email`、`zx_excel`、`manual`）。`source_id` 为空不代表手工：ZX 的来源关联也可能为空。
- 基金数、排序、日期截止和曲线以有效记录为准。原有 `apply_filter` 的净值大于 5 过滤仍保留，是历史展示规则，不等于数据已被删除。

## 净值与复权

单位、累计和复权净值是不同序列。`adj_nav` 是唯一规范复权字段，API 的 `adjusted_nav` 仅为兼容别名。

原邮件和 ZX 的复权公式核对后等价：首期复权值为 1，后续值为上一期复权值乘以 `(上一期单位净值 + 本期累计净值 - 上期累计净值) / 上期单位净值`。迁移保存原计算证据，并按完整有效历史重算。修改、删除或新增净值同样重算整个受影响基金。

若累计净值缺失或累计变化无法形成有限正数序列，整段复权净值缺失并返回原因。禁止逐点使用单位净值填补复权空值，避免虚构分红或收益。页面可以切换到单位或累计模式查看仍可用的数据。

## 指标参数保持原口径

本轮不统一不同历史模块原本采用的参数：

| 模块 | 既有口径 |
|---|---|
| 前端基金详情与对比 `formulae.js` | 年化 250 交易日或 50 周，无风险利率 1.75%，频率识别沿用原实现 |
| 后端指标摘要与组合指标 `_compute_fund_metrics` | 年化收益按 365 自然日，少于 30 日不报年化收益；波动率按相邻样本收益的样本标准差乘 √250；夏普无风险利率 2.5% |
| 首页区间收益 | 单位净值口径，沿用原区间起点取值规则；缺少所需样本返回缺失而非 0 |

因此不同模块的夏普/年化指标不应直接当成同一口径比较。界面显示缺失为 `—`；零仅表示实际算得零。

## 组合

保留 `UNIFIED_START`（统一起始，目标权重）和 `BATCH_INCLUDE`（分批纳入，目标金额）两种方式；不引入新的优化或再平衡策略。

- 统一起始：使用所有成分均有有效复权净值的公共日期，首个公共日期归一化，按目标权重求和；不把缺净值的持仓当作零。没有公共日期则明确拒绝计算。
- 分批纳入：基金在生效日期后的首个可用净值日加入；既有持仓缺少当日观察时沿用最后已知净值（LOCF，不使用未来数据）；新基金加入时按照目标金额比例重新分配。再分配前按当日已知净值重估原持仓，保留当日收益。
- 修复旧实现“缺一天就丢失持仓”和“再平衡漏掉当天收益”的错误；这是资产估值修正，不改变上述目标权重/金额方法。回归测试使用可手算的小样本。
- 缺少完整复权序列时不生成看似正常的组合。权重必须为有限正数且合计 100%，基金不能重复，日期必须真实有效。
- 计算结果附带输入指纹。基金净值、复权或组合定义变化后，旧缓存保留用于追溯，但不再作为当前净值展示，需要管理员重新计算。

## 同步状态

每轮记录开始/结束、处理邮件数、新增数、重复数和失败数。连接、认证、搜索、读取失败为失败；局部提取失败为部分成功；无新邮件为成功且新增 0。最后成功仅代表一轮完整成功，不等于净值已经更新到今天。

检查点与单封邮件的数据、来源、复权及统计一起提交。失败时回滚当前邮件，重启后可重放；已成功提交的邮件不丢失。新失败保存 UID/UIDVALIDITY、附件和工作表定位；缺少定位的旧失败会明确说明不能自动重试。

公开同步汇总不返回邮件主题、发件人或内部错误。管理员才能查看具体失败及重试结果。
